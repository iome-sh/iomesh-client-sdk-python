# 1.0 readiness bar (residual checklist)

> ## **NOT 1.0 YET**
>
> This document is a **future gate checklist** for a possible `1.0.0` major.
> Shipping **v0.10.0** (or any `0.x`) does **not** mean 1.0 is declared, released, or inventing GA.
>
> Framing that stays true until a real 1.0 ships:
>
> - MIT edge client only
> - **Beta** / pre-1.0 public APIs may still evolve within SemVer `0.x` norms
> - dual_write **OFF** by default elsewhere
> - **not** Memory GA · **not** freemium palace · **not** control-plane GA
> - Kafka **Produce subset** only until a consumer residual is intentionally scoped

Use this page to track residual work. Do not rebrand marketing or changelogs as “1.0” until every required gate below is checked with evidence.

---

## Required gates (all must pass)

### Tests

- [ ] Full `pytest` green on supported Python matrix (3.10–3.13) in CI
- [ ] Mock-HTTP unit coverage for every public Client method path that hits the wire
- [ ] No live broker credentials required in CI
- [ ] Known flake budget = 0 on main (or documented quarantines with owners)

### Docs

- [ ] [API.md](API.md) inventory complete and reviewed against `__all__` / public modules
- [ ] README honesty section still accurate (non-claims + residual Next)
- [ ] Examples runnable against local/stage broker with residual-honest headers
- [ ] RELEASING.md exercised at least once for the prior `0.x` tag flow

### Semver / API stability

- [ ] Explicit **breaking-change freeze** decision for public `iomeshclient` exports
- [ ] Deprecation policy documented (grace period for renames before 1.0)
- [ ] No silent wire breaks vs documented paths for core connect / publish / pull / KV
- [ ] CHANGELOG records any pre-1.0 deprecations

### Distribution (PyPI)

- [ ] Live **PyPI** publish of `iomeshclient` with `PYPI_TOKEN` (or Trusted Publisher)
- [ ] sdist + wheel install smoke: `pip install iomeshclient==1.0.0` (future)
- [ ] Wheel contains `iomeshclient/py.typed` (PEP 561)
- [ ] GitHub Release assets + tag `v1.0.0` only after gates

### Go parity matrix

- [ ] Documented matrix: Python surface vs Go `iomeshclient` / `kafka` / `connectorsdk`
- [ ] Intentional deltas listed (not accidental omissions)
- [ ] Fail-open semantics match Go where claimed (catalog / policy / context)
- [ ] Consumer pull / ack semantics match Go for HTTP plane

### Residual product honesty

- [ ] Kafka **consumer** residual resolved **or** explicitly deferred out of 1.0 scope in README
- [ ] Memory helpers remain dual_write OFF default; no Memory GA invent in 1.0 notes
- [ ] Liveview/registry remain edge HTTP helpers unless product elevates them
- [ ] Public lexicon remains heartbeat / pulse for org-tool dept.* events

### Quality tooling (recommended)

- [ ] Optional: mypy or pyright clean on `src/iomeshclient` (or documented baseline)
- [ ] ruff clean on `src` / `tests` / `examples`
- [ ] Import smoke + wheel contents check in CI release job

## Explicitly out of scope for “declare 1.0”

Do **not** treat these as automatic 1.0 unlocks:

| Temptation | Why it is not 1.0 |
|------------|-------------------|
| “v0.10 feels complete” | 0.x residual polish ≠ major stability promise |
| Tagging without PyPI | Distribution gate incomplete |
| Shipping Kafka Produce only forever without documenting deferral | Honesty gap on residual Next |

| Control-plane / freemium palace language | MIT edge client only |

## Suggested evidence for a future 1.0 PR

When (and only when) gates are met, a future release PR should include:

1. Version bump to **1.0.0** in `pyproject.toml` + `VERSION` + UA  
2. CHANGELOG section stating **stable public API** + any last deprecations removed  
3. Link to closed checklist items (CI run URLs, PyPI package URL, parity matrix doc)  
4. README Status line updated from Beta pre-1.0 → 1.0 stable **with honesty non-claims still intact** where product GA is not claimed  

Until then: remain on **0.x Beta**. Feature continuum tip: **v0.10.0**; docs wrap-up **v0.10.1** ([WRAP_UP.md](WRAP_UP.md)) — residual polish toward this bar only, **not** a 1.0 release.
